# Preparing for 3D

The game is 2D (top-down with extruded buildings) today. Everything below is already in place so that a 3D view can be added without
touching the simulation. **No 3D renderer exists yet**; this document describes what was prepared and what is left to do.

## What is prepared

| Piece | Where | Purpose |
| --- | --- | --- |
| Simulation without rendering code | `src/sim/*` | Deterministic, headless; a 3D client only reads state and sends orders. |
| Coordinate conventions + units | `src/sim/space.ts` | 1 tile = 4.5 m. Sim space (x east, y south, tile units) ⇄ 3D world space (X east, Z south, Y up, metres). Heading ⇄ yaw. |
| Real-world sizes | `vehicleDimensions`, `buildingHeightMeters` | Vehicle length/width/height in metres; building height = floors × 3.2 m. |
| Renderer-agnostic frame data | `src/sim/snapshot.ts` | `createSnapshot(world, alpha)` returns interpolated vehicles, people, cars, buildings (with floors/roof/model id/fire), incidents and obstacles, already in metres. |
| Renderer contract | `src/game/renderer.ts` | `GameRenderer`: `load(world)`, `render(snapshot, dt)`, `screenToTile`, `tileToScreen`, `centerOn`, `resize`, `destroy`. Orders only need tile coordinates (`World.contextOrder(ids, x, y)`), so picking = ray → ground plane → tile. |
| Model ids | `model` field on vehicle and role definitions (JSON), derived defaults `vehicle/<id>`, `person/<role>`, `building/<type>_<roof>` | Lets mods and a later asset pipeline map content to glTF models without code changes. |
| 3D-ready map data | `floors`, `roof` (`gable`/`hip`/`flat`) per building in `map_default.json`, generated by `tools/genmap.mjs` | Enough to extrude/roof buildings procedurally. Lane directions, intersections, parking bays and water tiles are all derived from the same grid. |
| Tests | `tests/unit/variety.test.ts` ("3D preparation") | Conversions, dimensions, snapshot interpolation and model overrides are covered. |

## Suggested plan for the 3D renderer

1. **Library:** three.js (MIT) — a small dependency, plain WebGL, no framework needed. Keep Phaser for 2D; load the 3D renderer lazily so the 2D build stays small.
2. **Scene:** one ground plane (terrain from `map.rows`: asphalt with lane markings, grass, parking, water), instanced meshes for trees and road markings.
   Buildings: procedural boxes from `heightMeters` with simple roof geometry from `roof` (gable/hip/flat) and window textures per `floors`. Burning buildings: emissive material + particle sprites driven by `fire`.
3. **Entities:** each frame call `createSnapshot(world, alpha)`; keep a `Map<id, Object3D>` and update position/`yaw` (diff, like `GameScene.track`). Start with box/primitive models generated from `size`; replace by glTF models via the `model` id.
   Use only CC0/own assets and list them in `THIRD_PARTY.md`.
4. **Camera:** perspective camera with an RTS rig (orbit around a target, WASD pan, wheel zoom, optional isometric preset with an orthographic camera).
5. **Input:** reuse the existing selection/order logic: raycast the pointer to the ground plane → `world3DToTile` → `World.pick/contextOrder`. Box select = project units to the screen and test against the rectangle.
6. **HUD, audio, settings:** unchanged (DOM + Web Audio). Add a *Weergave: 2D / 3D* setting and pick the renderer at game start; both read the same `World`.
7. **Performance:** instancing for civilians and pedestrians, frustum culling, shadows only for the closest buildings; target 60 FPS on integrated GPUs.

## Known gaps before 3D can ship

- Animated people (walking, carrying, spraying) and vehicle details (lights, ladders, hoses) need models/animations.
- Vehicles currently rotate instantly at corners; a 3D view wants smooth steering (the simulation could expose a `steer` angle or the renderer can smooth `heading`).
- Spatial audio uses the 2D camera centre; with a 3D camera it should use the camera position/orientation.
- The `GameScene` still reads the world directly; moving it onto `createSnapshot` (and the `GameRenderer` interface) is a mechanical refactor that can be done together with the first 3D renderer.
